# explanation ページ雛形

**理解**（背景・なぜ）を目的とする Diátaxis の explanation 区分。読者は文脈を知りたい。1 ドキュメント 1 区分に寄せる。

> explanation は「理解を深める解説」。reference（仕様）や how-to（手順）と混同しない——explanation は手順を示さず、設計の意図・トレードオフ・歴史的経緯を論じる。読者は手を止めて読む。

## frontmatter 例

```markdown
---
title: なぜ{対象}は{設計}なのか
diataxis: explanation
audience: 設計の背景を知りたい人
---
```

## 節構成

```markdown
# なぜ{対象}は{設計}なのか

{この解説で何を理解できるかを 1 文。読者が抱く疑問を言い当てる}

## 背景

{この設計が生まれた文脈・解決しようとした問題}

## 設計の考え方

{採用したモデル・原則。なぜそれが問題に適うか}

## トレードオフ

{採用によって得たもの・失ったもの。両側を正直に書く}

- **得たもの**: {利点}
- **失ったもの / 制約**: {コスト}

## 検討した代替

{採らなかった選択肢と、なぜ採らなかったか。実在の検討のみ書く}

## まとめ

{要点の再確認。決定の出典（ADR 等）への参照}
```

## 書き方の要点

- **Why に集中**: 「どうやるか」は how-to、「正確な仕様」は reference へ。explanation は「なぜそうなっているか」だけを論じる。
- **トレードオフを正直に**: 得たものと失ったものの両側を書く。一方的な利点の列挙にしない。
- **手順を書かない**: コマンドの実行列を載せない（載せたくなったら how-to に分ける）。
- **出典に接続**: 決定の根拠は ADR（正本ファイル）など正本へリンクし、解説内に決定を再定義しない。
