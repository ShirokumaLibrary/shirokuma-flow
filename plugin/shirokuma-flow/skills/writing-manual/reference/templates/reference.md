# reference ページ雛形

**参照**（正確な仕様）を目的とする Diátaxis の reference 区分。読者は特定の情報を調べに来る。1 ドキュメント 1 区分に寄せる。

> reference は「正確で網羅的な記述」。how-to（手順）や explanation（背景）と混同しない——reference は説明・誘導をせず、仕様を中立に・一貫した構造で並べる。読者は目次から目的の項を引く。

## frontmatter 例

```markdown
---
title: {対象}リファレンス
diataxis: reference
audience: 仕様を調べる利用者
---
```

## 節構成

```markdown
# {対象}リファレンス

{対象が何かを 1 文。網羅範囲を明示する}

## 一覧

| 項目 | 概要 |
|------|------|
| [{項目 A}](#{項目-a}) | {1 行説明} |
| [{項目 B}](#{項目-b}) | {1 行説明} |

## {項目 A}

{中立的な定義}

**構文 / シグネチャ**

```
{記法}
```

| 引数 / フィールド | 型 | 必須 | 説明 |
|-----------------|----|------|------|
| {name} | {type} | はい/いいえ | {説明} |

**戻り値 / 出力**: {説明}

**例**

```sh
{最小の使用例}
```

## {項目 B}

{同じ構造で並べる}
```

## 書き方の要点

- **構造を一貫させる**: すべての項目を同じ節構成（定義 → 構文 → 引数表 → 例）で並べる。読者が予測して引けるようにする。
- **中立記述**: 「おすすめ」「べき」を書かない。判断・誘導は how-to / explanation の役割。
- **網羅と正確さ**: 全項目・全引数を漏れなく。曖昧さを残さない（型・必須・既定値を明記）。
- **例は最小**: 各項目に最小の例を 1 つ。長いシナリオは how-to へ。
