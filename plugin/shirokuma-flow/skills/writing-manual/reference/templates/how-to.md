# how-to ページ雛形

**課題解決**（特定の作業を達成する手順）を目的とする Diátaxis の how-to 区分。読者は目的が明確で、その達成手順だけを求めて来る。1 ドキュメント 1 区分に寄せる。

> how-to は「目的を達成するためのレシピ」。tutorial（学習）と混同しない——how-to の読者は既に何をしたいか分かっており、最短で達成したい。基本の説明や背景は書かない。

## frontmatter 例

```markdown
---
title: {目的}する方法
diataxis: how-to
audience: {目的が明確な利用者}
---
```

## 節構成

```markdown
# {目的}する方法

{この手順で達成できることを 1 文。いつ使うかを明確に}

## 前提

- {この手順を始める前に満たすべき条件}

## 手順

1. {操作}

   ```sh
   {コマンド}
   ```

2. {操作}

3. {確認}: {結果が正しいことを確かめる方法}

## バリエーション

| やりたいこと | 方法 |
|------------|------|
| {派生ケース 1} | {対応する変更点} |
| {派生ケース 2} | {対応する変更点} |

## うまくいかないとき

- {よくある失敗と対処}

## 関連

- {前提となる手順 / 詳細仕様への参照}
```

## 書き方の要点

- **目的志向**: 「〜する方法」で始め、達成すべき結果を冒頭で示す。網羅的な機能解説にしない。
- **再現可能な手順**: 番号付きで順序を明確に。各手順は観測可能な結果を持つ。
- **背景を書かない**: 「なぜ」は explanation、「全選択肢」は reference へ。how-to は最短経路に絞る。
- **実在のケースに即す**: 想定する利用シーンを 1 つに絞り、派生は「バリエーション」表に逃がす。
