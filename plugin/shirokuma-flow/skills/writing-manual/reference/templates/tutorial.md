# tutorial ページ雛形

**学習**（手を動かして覚える）を目的とする Diátaxis の tutorial 区分。読者は初学者で、順に追って成功体験を得る。1 ドキュメント 1 区分に寄せる（他区分と混ぜない）。

> tutorial は「学習のための手引き」。how-to（課題解決）と混同しない——tutorial は読者がまだ何を求めるべきか分からない段階を導く。網羅性より**最後まで成功すること**を優先する。

## frontmatter 例

```markdown
---
title: {製品}をはじめる
diataxis: tutorial
audience: 初学者
---
```

## 節構成

```markdown
# {製品}をはじめる

このチュートリアルでは、{成果物}を最後まで作りながら {製品} の基本を学びます。
所要時間: 約 {N} 分。

## 前提

- {必要な環境・前提知識を最小限に}

## 完成形

{これから何を作るか。完成イメージを先に見せて到達点を共有する}

## ステップ 1: {最初の一歩}

{コマンド・操作を 1 つずつ。各ステップで「何が起きたか」を観測できる形に}

```sh
{コマンド}
```

期待される結果: {観測できる出力・状態}

## ステップ 2: {次の一歩}

{前のステップの結果の上に積む}

## ステップ N: {仕上げ}

## できたこと

{学んだことを振り返る。次に読むべき how-to / reference へ誘導}

- 次は: [{関連 how-to}]({リンク})
```

## 書き方の要点

- **必ず成功させる**: 分岐や例外を持ち込まない。一本道で最後まで通す。
- **理由を語りすぎない**: 「なぜ」は explanation の役割。tutorial では手を動かすことを優先し、深掘りはリンクで逃がす。
- **観測可能なステップ**: 各ステップで読者が「うまくいった」と分かる出力・状態を示す。
- **最小の前提**: 前提を増やすほど脱落する。インストール等は別 how-to に切り出して参照する。
