# 既存ページを共有アセットへ移行する

共有アセット（`assets/style.css` / `assets/theme.js` / `assets/modern-normalize.css`）を使わず**自己完結で**書かれた確認ビューは、`<style>` ブロックと `style=` 属性を持つ。共有アセットを置いたプロジェクトでは、それらが `lint areas docs` の `pages-no-inline-style`（**error**）に一斉に当たる。`lint areas docs` の areas は `--strict` に関わらず常に fail-closed なので、**移行が終わるまで赤が常態になる**。

**一時的に母集団から外す仕組みは用意しない**——外したことを戻す層が無く、その仕組み自体が恒久的な穴になる。**移行を完走する**のが既定で、枚数が多いときは 1 セッションで終わる量に分割して進める。

## 適用前提（外れたら手作業へ落とす）

下の手順 2 は**ページの骨格が次の形であること**に依存する: 本文が `<div class="wrap">` 1 枚に包まれ、`</body>` の直前にその閉じ `</div>` が来る。骨格が違うページにこの置換を当てると **DOM が壊れる**（しかも `pages-no-inline-style` は通りうるので、lint が緑でも壊れている）。**1 枚ずつ骨格を確かめ、違う形のページは手作業で `<main>` 化する。**

## 手順

1. **`<style>…</style>` を共有シートの `<link>` へ置換する**。読み込みは pages ルート直下の絶対パス（`/assets/modern-normalize.css?v=N` → `/assets/style.css?v=N`）で、`?v=N` はその pages に置かれている `assets/` の現物に合わせる。骨格の正本は `reference/template.html`。
2. **`<div class="wrap">` を `<main>` へ、`</body>` 直前の最後の `</div>` を `</main>` へ**（適用前提を満たすページのみ）。
3. **`</main>` の直後へ `theme.js` の `<script>` を追加する**（`defer` を付けない。位置と `?v=N` の値は `reference/template.html` に揃える）。
4. **色を持たない `style=` 属性を落とす**。**落とす前に assert を置く**（下記）。
5. **色を持つ `style=` 属性だけ共有シートのクラスへ写す**。`border` で色を持つものは `.summary-card.warn`、`color` を持つものは `.tag.ok` のように、**意味の合う既存クラス**へ寄せる（新しいクラスを増やす前に `grep -nE '\.tag(\.|,|\s*\{)' .shirokuma/pages/assets/style.css` でシートを引く）。

## 必ず含める 2 点（どちらも落とすと黙って壊れる）

### 手順 4 の前に assert を置く

落とす前に、**残りが色を含まないことを機械で確かめる**。確かめずに落とすと、**テーマ切替を壊すものを混ぜて落とす**（落とした側は差分にしか残らないので、後から気づけない）。

```bash
# 0 件であることを確認してから落とす（.shirokuma/pages/ を cwd にして実行）
grep -nEi "style=['\"][^'\"]*(color|background|border|shadow|outline|fill|stroke|#[0-9A-Fa-f]{3}|rgba?\(|hsla?\(|var\(--)" '{category}/{topic}/index.html'
```

- **`{category}` / `{topic}` は引用符の内側に置く**（上の形はそうしてある）。値は Issue / トピック由来なので、**単一引用符が守っている**——その内側では `$(…)` は展開されず、空白が入ってもコマンドは壊れない。**破れるのは値が `'` を含む場合だけ**である。したがって値域（slug 相当＝英数と `-` `_` `/`）を確かめてから差し込み、**引用符は外さない**（「値域を確かめるなら引用は要らない」と読み替えると、実際に守っている層のほうを落とすことになる）。
- **シングルクォートの `style='…'` も拾う**。
- **この grep は「色を持つ属性」の近似であって網羅ではない**（倒れる向きは **fail-open**＝色を持つ属性を「色なし」と読んで落とす側）。**拾わない形**: 上の語をどれも含まない**名前色だけの宣言**（`style='opacity:.5;fill:tomato'` は `fill` で拾えるが、語を持たない書き方は拾えない）／属性値を**改行で折り返した**形（`grep` は行単位）／`<style>` ブロック側の色（手順の対象が `style=` 属性なので別勘定）。**CSS の名前色 140 語の列挙は採らない**（誤検出と数え落としが同時に増える）。**拾えない形が残る前提で、落とす差分そのものも 1 枚ずつ目で見る。**
- **0 件のとき `grep` は exit 1 を返す**（「見つからない」が非 0）。**この行をスクリプトへ入れて `set -e` 下で回すと、成功条件のほうで落ちる。** 手作業で 0 件を確認する用途に限る。

### `issue-body-sha256` の行を消さない

`.shirokuma/pages/issues/{N}/index.html` が持つ `<!-- issue-body-sha256: <64 桁 hex> -->` を、`<style>` ブロックや冒頭のコメントごと消さない。**消すと `pages-issue-drift` が誤検知防止で skip し、検査そのものが黙って無くなる**。**倒れる向きは fail-silent**——検査が消えたことは lint の出力に現れず、赤にもならない。移行後にこの行が残っていることを 1 枚ずつ確かめる。

## 完了判定

移行した各ページについて `shirokuma-flow lint areas docs` が **`pages-no-inline-style` を 0 件**で返し、かつ **`pages-issue-drift` が skip に落ちていない**こと（`issue-body-sha256` を持っていたページについて）。**「移行した」だけでは完了にしない**——手順の実効性まで含めて lint で確かめる。
