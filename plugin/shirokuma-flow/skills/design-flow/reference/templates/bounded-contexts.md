# 境界づけられたコンテキスト雛形（bounded-contexts）

design-worker が **DDD を採用する課題**（[../criteria/ddd-adoption.md](../criteria/ddd-adoption.md) の採用契機に該当）で、ドメインを境界づけられたコンテキスト（BC）に分割するときに埋める雛形。プロジェクトの `domain/bounded-contexts.md` の下敷きにする。**DDD を採らない課題では作らない**（過剰なモデリングを避ける・非採用下限を参照）。

書き方の規律:

- **BC は構造（パッケージ / プラグイン / モジュール境界）を導出する起点**。既存の枠に合わせて BC を切るのではなく、BC から構造を導く。
- **コア / 支援 / 基盤で層別する**: 差別化の中核（コア）を厚く、必要だが差別化でない支援・全 BC が乗る基盤を薄く扱う（すべてを均等に厚くしない）。
- **ユビキタス言語の正本は glossary YAML**（`.shirokuma/glossary/<bc>.yaml`）。本ドキュメントは BC の責務と関係を定義し、語彙の定義は glossary へ寄せる（二重管理しない）。
- **BC 見出しは `#### {連番}. {BC 名}` で書く**（行頭が `####` ＋ 半角スペース ＋ 数字 ＋ `.` ＋ 半角スペース）。`auditing-docs` の **DDD レベル L1 以上**の検査はこの形の行を数え、0 件なら `ddd-artifact-empty`(error) になる。下の雛形本文の `#### 1. {BC 名…}` がそのままこの形なので、**検査は雛形を追認するだけで新しい書式を課さない**。
- **集約の不変条件（INV）は本書に置かない**（[domain-model.md](domain-model.md) へ送る）。本書の「不変条件」欄は BC 全体で守るルールで、集約 INV の機械検査は L2 で `domain/domain-model.md` に当たる。
- **儀式化しない**: DDD は実用的に借りる道具。BC 数を無理に増やさず、複雑さに見合う粒度で切る。
- 状態遷移・Issue 提出は orchestrator が flow verb で行う（worker は本文を作るだけ）。

---

```markdown
# 境界づけられたコンテキスト（Bounded Contexts）

{システム名} のドメインを {N} つの境界づけられたコンテキスト（BC）に分割する。各 BC が **パッケージ / プラグイン / モジュール境界の候補**であり、ユビキタス言語の有効範囲。{導出の根拠（コンセプト / 要件 / 既存構造）}から導出。

> **方針**: DDD は実用的に借りる（儀式化しない）。glossary YAML を正本にし、本ドキュメントは BC の責務と関係を定義する。

## 一覧

### コア（差別化の中核）

#### 1. {BC 名（英名・日本語補足）}
- **責務**: {この BC が担う中心的な関心。1〜2 文で}
- **核心概念**: {この BC のユビキタス言語の主要語（glossary の正本語）}
- **不変条件**: {この BC 全体で守るべきルール（集約 INV は domain-model へ）}

（差別化の中核となる BC を上に列挙）

### 支援（必要だが差別化でない）

#### {n}. {BC 名}
- **責務**: {…}
- **核心概念**: {…}

### 基盤（全 BC が乗る土台）

#### {n}. {BC 名}
- **責務**: {…}
- **核心概念**: {…}

## コンテキストマップ（BC 間の関係）

BC 間の関係を DDD の関係パターンで記述する（Partnership / Customer-Supplier / Conformist / ACL（腐敗防止層）/ Shared Kernel / 共有基盤 等）。

| 関係 | 種別 | 内容 |
|---|---|---|
| {BC-A} ↔ {BC-B} | {関係パターン} | {なぜその関係か・何が流れるか} |

## 構造へのマッピング（候補）

| BC | パッケージ / プラグイン / モジュール候補 |
|---|---|
| {BC 名} | {対応する実装単位の候補} |

> 既存の枠に縛られず、**BC から構造を導出する**。

## 次のステップ
1. BC ごとの glossary YAML（`.shirokuma/glossary/<bc>.yaml`）— ユビキタス言語の正本
2. ドメインモデル（集約・INV・ユースケース）— `domain/domain-model.md`（[domain-model.md](domain-model.md) 雛形）
3. ここから実装単位（パッケージ / モジュール / skill / CLI 等）を導出
```
