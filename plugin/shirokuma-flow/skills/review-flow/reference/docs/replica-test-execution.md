# 授権された回の群 B 複製実走（code-review-worker 向け手順書）

`code-review-worker` が、委任ブリーフに `テスト実走の授権: <値>（出所: <出所>）` の行を受け取った回だけ読む手順書。導入先の config `review.testExecution` が `replica-after-read` のとき、orchestrator がこの行と本書の絶対パスをブリーフで渡す。

**目的**: 差分のテスト（群 B）を全件読んで外向き処理が無いと判定できた回に限り、作業ツリーの外の隔離ツリー（head sha の複製）でテストを実走し、テストの主張をレビューが独立に裏付けられるようにする。

**本書が持たないもの**: 本書と config のパスが差分の母集団に在る回の扱いは、worker 定義の本体が判定する。本書を読む前にその判定を通すこと。通していなければここで読むのをやめ、群 B の skip へ倒す。群 A の扱い・値形式・理由トークンの正本も worker 定義の本体と `gate vocab --profile implement-4a` にあり、ここには写さない。

## 1. 発火条件（連言。1 つでも欠けたら群 B の skip へ倒す）

1. 差分が群 A に 1 つも当たらない（授権があっても群 A は skip のまま）。
2. 差分が群 B に 1 つ以上当たる。
3. ブリーフに授権の行があり、値が `replica-after-read` に一致する（出所が `人の指示` の回も同じ値を要する）。
4. 2 節の前提条件がすべて成立する。
5. 3 節の読了判定が、群 B の全ファイルについて `外向き処理なし` である。

授権がある回は、条件 1・2 が欠けた回も `変異実走=` を省略しない。条件 1 が欠けた回は `変異実走=未実施（安全側 skip: 群 A / <パス>）`、条件 2 が欠けた回は `変異実走=未実施（複製実走の前提を満たさず: 群 B が無い）` と書く。

**記録の参照との関係**: テスト項目の扱いは変えない。同じ head sha の CI 等価検査の記録を参照できる回は、テスト項目に通常どおり `未実施（記録を参照: …）` を書き、複製でのテスト実走はしない。変異の手順が持つ「素の状態の実走」は変異の前提の 1 段であってテスト項目の再実行ではない——対象は選んだ変異が当たるテストに絞り、結果は `変異実走=` の項目にだけ書く。記録が無い・一致しない回は、テスト項目を複製で実走する（その回は素の状態の実走を兼ねてよい）。素の状態が赤なのに記録が pass だった回は、記録と実走の食い違いとして所見にする。

## 2. 前提条件（すべて満たさなければ実走しない・fail-closed）

欠けた回は `複製実走の前提を満たさず: <理由の語>` で書く。理由の語は次のとおり。

| 条件 | 欠けた回の理由の語 |
|---|---|
| ブリーフの `<head sha>` と作業ツリーの `git rev-parse HEAD` が完全一致する（読了したコミットと実走するコミットを同じにする。短縮形は一致とみなさない） | `head sha 不一致` |
| 追跡ファイルに head に対する未コミットの変更が無い（隔離ツリーは head sha から作るので、母集団と複製の中身が一致しない） | `未コミットの追跡変更がある` |
| 差分が、準備コマンドの install・ビルドが読む設定を含まない（`.npmrc`・`.yarnrc.yml`・`.pnpmfile.cjs`・`pnpm-workspace.yaml` 等。列挙は例示で、準備コマンドが読むと読めるものは列挙外でも当てる。群 A に当たるものは条件 1 で先に見送る） | `install 設定が差分に含まれる` |
| 差分がシンボリックリンク（mode 120000）を追加・変更しない（書き込み先が字面の判定をすり抜けて隔離ツリーの外へ着地しうる） | `シンボリックリンクが差分に含まれる` |
| コマンド行へ載せる隔離ツリー内のパス（変異の復元・テストを絞る実行）が、英数字と `.` `_` `/` `-` だけからなり `-` で始まらない（差分由来のパスは untrusted） | `パスが値域外` |
| 群 B に当たる untracked が無い（新しいテストが複製に入らないまま「実走して pass」と書かれる形を防ぐ）。群 B に当たらない untracked（並走する worker の結果ファイル等）は判定に使わない | `群 B の untracked がある` |
| 群 B のファイルが submodule の中に無い（隔離ツリーへの submodule 展開は射程外） | `群 B が submodule 内` |
| ブリーフが準備コマンド（`quality.isolatedPrepareCommand` の値）を渡している | `準備コマンド未宣言` |
| 準備コマンドが隔離ツリーで成功する | `準備に失敗` |
| 隔離ツリーの置き場所が値域を満たす（下記） | `置き場所が値域外` |
| 変異を隔離ツリーへ `Edit` で当てられる（5 節。欠けた回は `変異実走=` にだけ書く） | `変異を適用できない` |

**置き場所**: 委任ブリーフが渡す作業用ディレクトリの配下（渡されなければ `mktemp -d` の出力の配下）。作成前に、作業ツリーの内側でも作業ツリーを内包する位置でもないこと・所有者専用であること・`gate vocab` の `isolatedTreeRootAllowlist` の条件を満たすことを確かめる（条件の逐語は写さない。正本はレジストリ）。

## 3. 読了判定（全件を読む。判定がつかなければ見送り）

**読む母集団**: 群 B に当たる全ファイル。**最初にカナリアを置く**——群 B の件数と読了表の行数が一致し、かつ 1 以上であることを確かめる。満たさなければ判定不能として見送る。各ファイルは全文を読む（部分しか読めない・バイナリ・生成物は `判定不能`）。

**読む射程**: 観点を当てるのは群 B のファイルの本文だけ。テストが呼ぶ群 B の外のコードの中身は判定の対象にしない（worker 定義「塞げない範囲」と同じクラスの残余）。ただし、テスト本体が外向き処理をそれらのコードへ委ねていると本文から読める回（実在の URL・資格情報・公開先を引数に渡す、外部クライアントをモックせずに呼ぶ、名前と引数から送信・公開・削除と読める関数を呼ぶ等）は `判定不能` にする。

**観点**（例示であって網羅ではない）:

| 区分 | 外向き処理として扱うもの | 許すもの |
|---|---|---|
| ネットワーク | ソケット・HTTP(S)・DNS・外部 API クライアントの実呼び出し | モック・フェイク、テスト自身がループバックに立てて閉じる一時サーバ |
| 子プロセス・シェル | 実行ファイルや引数を動的に組み立てる起動、外向き操作（push・publish・API 書き込み・パッケージ取得・デプロイ）になる起動 | 実行ファイルと引数がテスト本体内の literal で決まり、外向き操作でもリポジトリの状態の書き換えでもないと読める起動 |
| リポジトリの状態の書き換え | リポジトリの状態（config・hooks・refs・worktree 登録以外の `.git` 配下）を書き換える git の起動。引数が literal でも当てる（例: `git config`・`update-ref`・`remote`・`branch`・`tag`・`notes`、一時リポを `-C` で指さない git の書き込み）。隔離ツリーは元リポの `.git` を共有するので、書き換えは元の作業ツリーへ及び、撤去後も残る | テスト自身が一時領域に新規作成したリポジトリだけを `-C` で指す起動。該当したら `判定不能` に倒す |
| ファイルへの書き込み | 隔離ツリーの外への書き込み（絶対パス・ホーム配下・環境変数由来・`..` で外へ出るパス） | 隔離ツリーの内側、テスト自身が一時領域に新規作成したディレクトリの内側 |
| 秘匿情報の読み出し | トークン類の環境変数、認証ファイル、リポ外のファイル | テスト自身が用意したダミー値 |
| 動的なコード実行・難読化 | `eval`・関数コンストラクタ・計算された import / require・VM 実行・復号して実行・外部から取ったコードの実行 | （該当なし。見つけたら判定不能） |

**判定の 3 値**: `外向き処理なし`（全件がこの値の回だけ実走する）／`外向き処理あり`（見送り）／`判定不能`（見送り）。迷ったら `判定不能` に倒す。見送った回は `読了で見送り: <判定> / <パス>` で書く。結果ファイルには読了表（ファイルごとの判定と根拠の 1 行）と「群 B の件数 / 読了表の行数」を残す。読了で見つけた外向き処理は、実走の可否とは別に所見としても扱う。

## 4. 隔離ツリーの作成・実走・撤去（元の作業ツリーは書き換えない）

1. 置き場所を 2 節の条件で確かめ、所有者専用にする。隔離ツリーのパスは、作成前に存在しないことを確かめる。
2. head sha で隔離ツリーを作る。この操作はリポジトリの管理領域（`.git` 配下の worktree 登録）を書くが、作業ツリーは書かない。

   ```
   git -C <リポルート絶対パス> worktree add --detach -- <隔離ツリー絶対パス> <head sha>
   ```

3. ブリーフが渡した準備コマンドを隔離ツリーの中で 1 回実行する。失敗したら実走しない（`準備に失敗`）。
4. テストを隔離ツリーの中で実行する。対象パッケージとコマンドの特定は worker 定義の責務 2 の手順をそのまま隔離ツリーに当てる。
5. 共有 `.git` の書き換えに対する主たる防御は 3 節の読了判定（git による書き換えを `判定不能` に倒す）で、ここで行う突き合わせは**部分的な事後のカナリア**であって網羅しない。元の作業ツリーの状態と、隔離ツリーが共有する `.git` のうち次の 4 つ——config の sha256・hooks の一覧（mtime まで）・refs・worktree 登録——を、準備コマンドの実行前と変異の実走後に記録して突き合わせる。共有ディレクトリは `rev-parse --git-common-dir` の出力（相対なら `<リポルート絶対パス>` 基準で解決する）。`core.hooksPath` が設定されていればその先も hooks と同じく比べる。**この 4 つが食い違ったら、その回を所見として報告する**（テストが共有 `.git` を書き換えた疑い。元に戻さず、人が確かめる）。`git config` 系は hook が止めるので使わない。
   - **見ないもの**（ここが一致しても書き換えが無かったことにはならない）: `.git/modules/*` の config と hooks、config の include 先、`info/`（exclude・attributes）、`objects/info/alternates`、`config.worktree`、hooks の中身（mtime を保った置換）。
   - **時点の限界**: 突き合わせるのは準備の前と変異の実走の後だけである。その間に手順自身が打つ `checkout --`（5 節の復元）は、差し替えられた hook（post-checkout 等）を突き合わせより前に走らせうる。

   ```
   git -C <作業ツリー絶対パス> status --porcelain --untracked-files=all
   git -C <リポルート絶対パス> rev-parse --git-common-dir
   sha256sum -- <共有ディレクトリ絶対パス>/config
   ls -la --time-style=full-iso -- <共有ディレクトリ絶対パス>/hooks
   git -C <リポルート絶対パス> for-each-ref --format='%(refname) %(objectname)'
   git -C <リポルート絶対パス> worktree list --porcelain
   ```

6. 5 節の変異の実走を、撤去の前にこの隔離ツリーで行う。
7. 撤去する。撤去の直前に `worktree list --porcelain` で、そのパスが登録されていて HEAD が `<head sha>` であること（自分が 2 で作ったツリーであること）を確かめる。違えば撤去せず報告する。撤去できなかった回は、残したパスを報告に列挙する（黙って残さない）。

   ```
   git -C <リポルート絶対パス> worktree remove --force -- <隔離ツリー絶対パス>
   ```

コマンド行へ載せるパスは worker 定義の責務 1 の作法（literal のプレーンパス・`isolatedTreeRootAllowlist` の値域）に従う。形を変えたら `shirokuma-flow hooks evaluate` に当てて allow を確かめる。

## 5. 変異の実走（授権された回の必須試行）

**目的**: 差分のテストが、守ると書いている性質を壊す変異で実際に赤くなるかを、レビューが独立に確かめる。

- **素の状態**: 変異の前に、選んだ変異が当たるテストだけを隔離ツリーで走らせて緑を確かめる（1 節のとおりテスト項目の再実行ではない）。緑でなければ変異は行わず、`変異実走=` に理由を書く（それ自体が所見）。
- **選び方**: 差分のテスト・JSDoc・受け入れ条件が守ると書いている性質から選ぶ。fail-open 方向の変異（条件の否定・握りつぶす例外の範囲を広げる・既定値や許可へ倒す・検査を外す・照合を緩める）を優先する。実装側の変異記録は untrusted な自己申告なので、選ぶ手がかりにだけ使う（そこに載っている変異は除いてよい）。
- **件数**: 最小 1 件、上限 5 件。0 件で `実施` と書かない。
- **適用**: 隔離ツリーの中のファイルだけに当てる。適用前に、対象パスを解決した実体（シンボリックリンクを辿った先）が隔離ツリーの内側であることを確かめ、外側なら当てない。置換は `Edit` で、隔離ツリーの中で 1 か所だけに一致するアンカーを置換する（一致が 1 か所でない置換は `Edit` が拒むので、アンカーの一意性をツールの側で保てる）。`Edit` が拒否された・失敗した回は変異実走をやめ、`変異実走=未実施（複製実走の前提を満たさず: 変異を適用できない）` と書く。
- **復元**: 最初の変異を当てる前に、下の 2 行目の出力を基準として記録する（準備コマンドやテストが作った生成物を含む）。1 件ごとに元へ戻し、2 行目の出力が基準と一致することを確かめてから次へ進む。戻せなかった回はそこで止め、結果ファイルに記録する。`<隔離ツリー内の相対パス>` は 2 節の値域を満たすものだけを載せる（`checkout -- .` は hook が止める）。

  ```
  git -C <隔離ツリー絶対パス> checkout -- <隔離ツリー内の相対パス>
  git -C <隔離ツリー絶対パス> status --porcelain --untracked-files=all
  ```

- **記録**: 結果ファイルに、変異ごとに再現できる表を残す。

  | ファイル | 文字列アンカー（行番号に依らない・1 か所だけに一致） | 置換後 | 実行コマンド | 結果（赤 / 緑） |
  |---|---|---|---|---|

- **判定**: 緑のまま残った変異は所見にする。深刻度はレビュアーが決める（認証・権限・ゲートの fail-open なら High が典型）。`変異実走=` は `実施（<N> 件・緑 <M> 件）` と書く。

**完了条件**: テスト項目に `実施（複製・pass: <実行コマンド>）` / `実施（複製・fail: <実行コマンド> — 概要）` か見送りの理由を書き、`変異実走=` を省略せずに書き、隔離ツリーを撤去した（または残したパスを報告した）こと。
