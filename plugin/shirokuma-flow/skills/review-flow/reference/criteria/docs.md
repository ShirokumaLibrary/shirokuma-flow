# ドキュメントレビュー観点（docs）

review-worker が Markdown ドキュメント・GitHub 成果物（Issue / Discussion 本文）をレビューする際の判定基準。

> レポート雛形は [../templates/report.md](../templates/report.md)。

**適用の流れ**: 各観点とアンチパターンで検出 → 末尾の「判定」節で PASS / NEEDS_REVISION を決める。**検出段では指摘を深刻度に関わらず全件列挙し、絞り込みは判定節で行う**（検出段で絞ると低深刻度の所見が失われる）。

## Markdown 構造

- [ ] 一般的な Markdown の作法（見出し階層のスキップ無し・h1 は 1 つ・空セクション無し・リストとテーブルの一貫・コードブロックの言語指定と構文の正しさ）に沿う

## リンク整合性

- [ ] 内部リンク・アンカーが実在の先へ解決し、相対パスが正しい（内部参照のハードコード URL・外部リポジトリや旧名称への恒久参照は指摘）

## 内容の正確性（コードベースとの一致）

- [ ] 記載のコマンド・パス・API・バージョン・サンプルコードの引数と順序とフィールド名が実装と一致し（grep / Read で照合）、古い情報（廃止仕様・TODO / FIXME の残存・旧 CLI の例）が無い

## 用語・表記の一貫性

- [ ] プロジェクト固有の用語・数値・単位・略称の表記が統一され（例: `review-worker` と `review worker` の混在）、略語の初出に正式名称がある

## GitHub 成果物（Issue / Discussion）固有の観点

- [ ] 種別に適した形式になっているか（ADR なら Why-first の節構成、Issue なら必須セクションが揃っているか）
- [ ] **YAML フロントマター混入**: 本文先頭に `---` で始まるメタデータブロックが本文として表示されていないか
- [ ] **クロスリファレンス整合性**: 参照している `#N` が実在し、文脈と一致しているか（`Closes #N` / `Refs #N` の参照先・ADR 番号）
- [ ] タイトル形式が種別の規約に従っているか

## プラグイン自己完結（プラグインのソースの変更時）

変更対象にプラグインのソース（`.claude-plugin/plugin.json` を持つディレクトリの配下）の Markdown が含まれるときは [plugin-portability.md](plugin-portability.md) のハード観点（PP1〜PP3）を適用する。**本節では観点の中身を要約しない**——要約は条件を落として本体より緩い基準になり、要約だけを読んだレビュアーが「ハード観点を確認した」つもりで逆の判定を出す（倒れる向きは fail-open）。該当の可否も自動 NG の強度も同ファイルの本文が正本なので、そちらを読んで当てる。

## 委任・検査に触れる変更（対象種別によらず適用・正本は [[delegation-and-checks]]）

変更が **委任（worker / skill / 手順への割り当て）または検査（ゲート・判定条件・決定表・lint ルール・レビュー観点・テストによる機械検証）に触れている可能性がある**なら、[[delegation-and-checks]] を読んで実際の発火条件を当て、該当したら同規範の D 節 / C 節で見て同規範が定める深刻度で指摘する。

観点・発火条件・深刻度の正本は同規範側にあり、**本ファイルは条件を写さない**（写した要約が本体より緩くなる形＝同規範 C5 を避ける）。上の開閉条件は正本より広く取ってあり、当たりすぎることはあっても当たらなくなることはない。**対象種別が docs でも適用する**——委任も検査も Markdown（SKILL.md・agent 定義・criteria・reference）の変更として現れることが多く、種別で振り分けると**その形の変更だけが一度も通らない**。

## 検出すべきアンチパターン

上の各観点の裏返し（フロントマター混入・存在しない番号への参照・コマンドやパスの不一致・表記ゆれ・正本が不明な重複情報）。

## 判定（PASS / NEEDS_REVISION の決め方）

検出をすべて終えたあとに、列挙済みの指摘から判定する。

- **判定は High 以上の指摘があれば NEEDS_REVISION**。プラグイン自己完結のハード観点該当も NEEDS_REVISION（自動 NG）。
- High が無く Medium 以下のみなら PASS（指摘はレポートに記載する。対応は著者の任意）。
